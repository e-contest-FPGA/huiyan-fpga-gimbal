# V20S2F2 / V21F1 实机对照

当前实机基线是 V20S2F2。V21F1 的实物对照尚未采集。两版已有的公开证据和源归档哈希见[版本证据](evidence.md)与[来源清单](source-provenance.json)。

## 采集设置

同一块板、相机、供电、安装位置、目标、照明和显示器分别运行两版。先用固定相机检查框，再启用云台。每次记录固件 SHA-256、SW1–SW4 状态、目标距离和录制帧率。先保留案例原视频，再选片段用于展示。

每版每场景至少重复 5 次。变更固件时用 SRAM 下载，按[上板步骤](hardware.md#上电顺序)从 SW3 下拨开始。相机固定与云台跟随使用不同记录行。

| 场景 | 操作 | 记录什么 |
| --- | --- | --- |
| 浅色背景 | 白墙或浅色桌面前锁定一个有对比度的物体，再从左移到右 | 目标完整可见的帧数、框选中背景的帧数、丢失帧数 |
| 同色干扰 | 锁定原目标后让另一件同色物体经过 | 误换目标次数、进入保持的次数、原目标找回次数 |
| 短暂遮挡 | 遮挡约一秒，移开遮挡后保留原目标 | 重新看到目标至恢复有效框的时间、云台有无误跟随 |
| 跟随与停稳 | 重复相同路径和速度，随后让目标静止 | 起转时间、停稳时间、是否出现反向摆动 |

## 统计口径

- 每次事件按录像及人工标注判定。误锁是框转移到干扰物或背景，并持续至少三个摄像头帧。录像帧率与摄像头采集帧率不同时，按三个采集帧周期换算持续时间。
- 找回时间从遮挡解除且目标重新可见开始，到目标框连续三帧回到原目标为止。计时窗口内未恢复写 `not_found`。
- 机械起转、停稳和屏幕帧龄各自记录。逐帧计时使用原始录像帧率，至少报告一帧的量化间隔。报告包括样本数与失败次数。
- 对照表用[实机记录模板](hardware-run-template.csv)记录。空值表示待测。未实测时保留空值，复测报告里附可访问的原始记录和固件哈希。

可接受的发布证据至少包括两版相同设置的原视频、每类尝试的汇总，以及能让他人核对误锁和找回判断的帧号或时间点。
